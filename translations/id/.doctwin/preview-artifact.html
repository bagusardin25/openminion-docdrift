## Quick Start For a real model-backed session, start with the bare command: ```bash openminion --version openminion --dir "$PWD" ``` Setup asks for a provider, model, and credential. For built-in providers, OpenMinion selects the API adapter automatically. For example, MiniMax remains the provider when it uses an OpenAI-compatible API. Press Enter at the hosted provider check to send one recommended test request before Focus opens; the request may consume a small amount of quota. Use the provider-list commands above for the current human-readable or machine-readable catalog. An explicit `--dir` trusts that workspace for the current process. A bare launch also trusts an ordinary Git worktree; another implicit directory starts Read only. Launching from your home directory or a filesystem root requires an explicit `--dir PATH`. Add another existing directory for the current process with repeatable `--add-dir PATH` options: ```bash openminion --dir "$PWD" --add-dir ../shared ``` Structured file tools remain confined to the workspace, explicitly added directories, and configured policy roots. Host commands remain disabled when no sandbox is configured. `--allow-unsandboxed-exec` is an explicit opt-in: commands then use the OpenMinion process's OS permissions and are not confined to workspace roots; command policy and approvals still apply. A native local sandbox and approval-free command parity are not provided yet. In Focus, `/permissions` opens Read only, Ask, Workspace auto, and Full access. Workspace auto is intentionally narrow: only `file.write` and `file.edit` skip their ordinary prompt, and workspace/path enforcement remains active. Full access requires confirmation and does not bypass configured block/ask rules, selected denies, host-execution enablement, exact financial or operations authorization, or `project.start`. Permission posture and exact-session grants persist with the OpenMinion session; `/permissions grants` lists active grants and `/permissions revoke <grant-id>` removes one. For a durable action-policy default, put `action_policy` at the config root or under one agent profile. The per-agent form is: ```json { "agents": { "local-coder": { "provider": "openai", "action_policy": {"mode": "bypass"} } } } ``` This disables ordinary action-policy prompts for that agent, but it is not a persistent Full access switch: Full access also sets the session tool permission mode. `permission_mode` is not supported inside `agents.<id>`. Select Full access through `/permissions` and reuse the same session, or pass `permission_mode` as a trusted API/request input. See [Getting Started](docs/getting-started.md#persistent-action-policy-defaults). When setup finishes and the interactive CLI opens, ask: `List this workspace using the file tools.` The default config is saved at `~/.openminion/agents.json`, so the next bare launch reuses it. Direct `openminion mcp ...` commands use `./.openminion/agents.json` when `--config` is omitted, matching the Python SDK's project-scoped default. Pass `--config ~/.openminion/agents.json` to manage the interactive setup config instead. MCP commands that change configuration report the exact `config_path` they wrote. For a credential-free product tour, create an explicit echo/demo config: ```bash openminion config init --provider echo openminion run "hello" openminion status readiness ``` Demo mode exercises configuration, storage, sessions, and CLI plumbing, but it does not call a model or prove provider-backed task quality. Readiness reports label this state `demo`, not `ready`. Open the interactive CLI: ```bash openminion --dir "$PWD" ``` Run two configured agents in one Focus room with explicit runtime roots: ```bash runtime_root="$PWD/.openminion-room" config_path="$HOME/.openminion/agents.json" room_output="$(openminion \ --home-root "$runtime_root/home" \ --data-root "$runtime_root/data" \ --config "$config_path" \ room create \ --name "Review room" \ --human owner-local \ --agent writer \ --agent reviewer \ --channel console \ --target focus)" room_id="$(printf '%s\n' "$room_output" | sed -n 's/^room=//p')" openminion \ --home-root "$runtime_root/home" \ --data-root "$runtime_root/data" \ --config "$config_path" \ --agent writer \ --session "$room_id" \ --dir "$PWD" ``` Inside Focus, use `/participants` to inspect the room, `/routing broadcast` or `/routing sequential` to change its mode, and address one agent with `@reviewer`. Room mutations require the local owner; participants can post and observers cannot. Embed an isolated agent session from Python: ```python from openminion import Agent, ProviderError, tool @tool(min_scope="READ_ONLY", idempotent=True) def lookup_order(order_id: str) -> str: return f"order {order_id}: ready" try: with Agent( instructions="Answer briefly.", tools=[lookup_order], session_id="customer-42", ) as agent: result = agent.run("Check order A-104") print(result.text, result.session_id) except ProviderError as exc: print(f"provider failed: {exc}") ``` `lookup_order` declares itself read-only, so the default action policy runs it without a confirmation. Under the same policy a bare `@tool` is treated as a write and is confirmed first; see [Runtime surfaces](docs/runtime-surfaces.md) for how the `@tool` options map to approval. Pass `config_path="path/to/agents.json"` to use a project-owned config and `agent_id="reviewer"` to select one configured profile. For advanced runtime composition, construct `APIRuntime` directly and pass it as `runtime=` instead. See [`examples/starter/quickstart.py`](examples/starter/quickstart.py) for the complete runnable example and [`docs/getting-started.md`](docs/getting-started.md) for contributor bootstrap.

A `file.read` includes `content_sha256` for the full UTF-8 text before newline conversion or slicing. Local reads retain their existing universal-newline text view; the fingerprint distinguishes the original LF, CRLF and CR bytes. In-memory reads preserve the original newline characters. Complete local reads also include an opaque `version`. For conditional overwrites, `file.write` accepts `expected_content_sha256` (pass `content_sha256` from the read directly) and `expected_version`. A mismatch returns `PRECONDITION_FAILED` before truncation. Conditional append is rejected. Local conditional replacement requires advisory file locking and fails closed when it is unavailable; the locks coordinate participating writers, not arbitrary external processes. The in-memory backend supports the content precondition. The adaptive loop permits one identical safe read retry after a structured transient failure. It can also retry an identical overwrite once after a complete, same-path readback contradicts the acknowledged content, adding the content and available version preconditions. Permissions and budgets are checked again. Append, external effects and partial readbacks do not receive this recovery. ## Automatic fact extraction Automatic fact extraction is enabled by default. When it runs, the turn makes one auxiliary structured model call before the user message is interpreted. The call asks for candidate facts, user preferences and tasks that the user stated explicitly. Its result is staged as memory candidates; it is not part of the reply. The supported switch is the top-level `brain.auto_fact_extraction` section: | Field | Default | Meaning | | --- | --- | --- | | `enabled` | `true` | Run extraction on eligible turns. | | `model_tier` | `reflect` | Model tier used to pick the extraction model. | | `max_items_per_turn` | `5` | Maximum candidates requested from one message. | | `min_user_message_chars` | `8` | Shorter messages, after trimming, are skipped. | | `initial_confidence` | `0.3` | Confidence given to staged candidates. | | `timeout_seconds` | `20` | Transport read timeout for the call; not a bound on total extraction time (#634). | ```json { "brain": { "auto_fact_extraction": {"enabled": false} } } ``` An `auto_fact_extraction` key under `agents.<id>` currently has no effect. The agent-profile parser does not read it, and the top-level section stays in force. The model comes from the effective agent profile. With the default `reflect` tier, extraction uses `reflect_model`, then `decide_model`, then `act_model`, whichever is set first. It is not necessarily the model of the main action request. Another tier tries `<tier>_model`, then `reflect_model`, then `decide_model`. The call goes through the existing structured-output retry path. It is one logical extraction call, but it can make more than one provider request, and billed usage is a separate measurement. The turn's LLM-call counter records it only when the structured call returns, so a provider failure can leave a model request uncounted; the counter is not a count of attempted provider requests. It offers only the forced `submit_output` structured-output tool. That tool list belongs to this auxiliary call: the turn's later entry and action requests carry their own tools. Extraction does not run when: - `enabled` is `false`; - the message is shorter than `min_user_message_chars`; - the message is an explicit `tool <name> ...` command; - capture is excluded for the turn or memory writes are not authorized for it; - the turn skips its initial user-message append; - the LLM, context or memory service is unavailable, or no extraction model is configured. A failed extraction emits `brain.auto_fact_extraction.skipped` with reason `extraction_failed`, and the turn continues. The `started`, `completed` and `skipped` events of `brain.auto_fact_extraction` show what happened on a given turn. When you measure request counts or cost, account for this call on its own, or compare with `enabled` set to `false` as one changed setting.

## Handoff approval `delegation.py --mode handoff` exposes the researcher as a `transfer_to_researcher` tool. A `Handoff` declares no risk metadata, so the policy keeps it on the unknown-reversibility default and pauses for confirmation before the target runs. - Without an `approval_callback`, the run ends at that pause: `result.text` is the operator prompt ("Policy confirmation required. …"), not the researcher's answer, and `result.metadata["respond_kind"]` is `policy_confirmation_prompt`. Application code that keeps its Agent open answers it on the waiting thread with `agent.run("yes", thread_id=result.thread_id)`; a plain later `run()` starts a new thread and does not answer it. - With `approval_callback`, the callback decides for that call before the target runs: returning true allows that one invocation; returning false ends the turn with "Confirmation denied. The action was not run."; a callback that raises fails the run with that error. In both failure cases the researcher does not run.
